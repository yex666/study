## 🎯 先搞清楚：Coding Agent 到底在干什么？

在你开始写代码之前，先想清楚一个问题：

**Coding Agent = 一个能自主使用工具来完成编程任务的 AI**

用户说："帮我重构这个函数"

Agent 的工作流程：
```
1. 思考：我需要先看看这个函数长什么样
2. 行动：调用 read_file("main.py")
3. 观察：看到函数代码
4. 思考：这个函数太长了，需要拆分
5. 行动：调用 write_file("helper.py", new_code)
6. 观察：文件写入成功
7. 思考：还需要更新原来的文件
8. 行动：调用 edit_file("main.py", ...)
9. ...
10. 思考：完成了！
11. 回答用户："我已经帮你重构好了"
```

**核心就是一个循环**：
```python
while True:
    # 问 AI：下一步做什么？
    response = await llm.chat(history)
    
    # 如果 AI 说要调用工具
    if response.has_tool_calls():
        # 执行工具
        for tool_call in response.tool_calls:
            result = await execute_tool(tool_call)
            history.append(result)
    else:
        # 没有工具调用，说明完成了
        return response.text
```

就这么简单！**其他所有东西都是为了让这个循环更可靠、更好用。**

## 🔍 每个组件快速预览

下面我用**最简短的话**告诉你每个组件是干什么的。详细的解释在各自的文档里。

### 核心引擎层（最重要！）

| 组件 | 一句话解释 | 为什么需要 | 不 doing 会怎样 |
|------|-----------|-----------|----------------|
| **Agent Loop** | 思考→行动→观察的循环 | 这是 Agent 的"大脑" | 只能单轮对话，不能连续执行任务 |
| **LLM Client** | 和 AI 模型对话的接口 | 要和 OpenAI/Claude 等通信 | 只能用固定的一家模型 |
| **Tool System** | 定义和执行工具的框架 | Agent 需要读写文件、执行命令 | 只能说不能做 |
| **Middleware** | 在调用前后插入逻辑 | 需要审批、日志等功能 | 无法扩展，硬编码所有逻辑 |
| **Context Mgmt** | 管理对话历史 | LLM 有上下文窗口限制 | 对话太长就崩溃或丢失信息 |

### 服务层（让 Agent 更强大）

| 组件 | 一句话解释 | 为什么需要 | 不 doing 会怎样 |
|------|-----------|-----------|----------------|
| **Profiles** | 配置不同的 Agent 和模型 | 不同任务需要不同配置 | 每次都要手动改代码 |
| **MCP** | 连接外部工具 | 要用 GitHub、Jira 等 | 只能用自己的工具 |
| **Skills** | 可复用的知识包 | 通用知识要共享 | 每个 Agent 都要重复教 |
| **Hooks** | 特定时机执行自定义逻辑 | 想在工具调用前检查参数 | 无法灵活扩展 |
| **Approval** | 控制哪些操作需要确认 | 删文件很危险 | 可能误删重要文件 |
| **Workflows** | 预定义的多步骤流程 | 复杂任务有固定流程 | 每次都要从头描述 |
| **Memory** | 跨会话记住东西 | 记住用户偏好和项目约定 | 每次都要重新教 |

### 编排层（让系统更可靠）

| 组件 | 一句话解释 | 为什么需要 | 不 doing 会怎样 |
|------|-----------|-----------|----------------|
| **Session Host** | 管理一次完整的对话 | 要保存状态、处理中断 | 关掉程序就丢了进度 |
| **Execution Lease** | 防止同时干两件事 | 不能同时跑两个 turn | 状态混乱，数据损坏 |
| **Turn Coordinator** | 协调一轮对话的开始和结束 | 要处理准入、重试、回滚 | 无法处理并发和错误 |

### 用户界面层（让用户能用）

| 组件 | 一句话解释 | 为什么需要 | 不 doing 会怎样 |
|------|-----------|-----------|----------------|
| **TUI** | 终端里的图形界面 | 用户体验好 | 只能用原始命令行 |
| **Headless CLI** | 纯命令行模式 | CI/CD 和脚本使用 | 无法自动化 |
| **ACP Server** | API 接口 | 其他程序调用 | 无法集成到其他工具 |

### 基础设施层（底层支撑）

| 组件 | 一句话解释 | 为什么需要 | 不 doing 会怎样 |
|------|-----------|-----------|----------------|
| **EventBus** | 模块间通信 | 解耦，各模块独立 | 紧耦合，难以维护 |
| **Settings** | 配置管理 | 用户要改设置 | 硬编码所有配置 |
| **Platform** | 跨平台支持 | 要在 Win/Mac/Linux 跑 | 只能在一个系统上用 |
| **i18n** | 多语言支持 | 不同国家用户 | 只有英文界面 |
